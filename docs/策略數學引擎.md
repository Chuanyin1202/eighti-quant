# 策略數學引擎

**文件目標：** 定義策略 `Step()` 函數的完整輸入輸出契約，以及內部各層（市場狀態感知 / 宏觀引擎 / 微觀引擎 / 底倉釋放）的計算邏輯。本文件是 `internal/strategies/lunar-spot-v1/` 所有程式碼的**唯一**規格依據。

**主線設定：** `lunar-spot-v1` 策略，運行於 Binance 現貨 BTCUSDT / ETHUSDT 雙標的，聚合週期 4h。

---

## 0. 引擎身份

### 0.1 純函數無狀態轉換器

`Step()` 是一個純函數：

```
Step(input StrategyInput, params Params) → output StrategyOutput
```

- 相同 `input + params` **必定**產出相同 `output`（無隨機、無時鐘、無外部依賴）
- 函數內**禁止**：`time.Now()` / `http.*` / `database/sql.*` / `os.Open` / `gorm.*` / 計時器
- 所有時間戳、K 線、帳戶狀態必須由 `input` 傳入

### 0.2 鐵律複述

1. **複利前置**：策略設計必須能說明資金規模如何隨權益正反饋滾動
2. **回測=實盤同構**：禁止 `if isBacktest` 分支
3. **無 I/O**：禁止網路、DB、檔案、計時器
4. **OHLC 剝離**：本策略 `IsSpot=true`，內核只接受 `[]float64 closes` 與 `[]int64 timestamps`，不依賴 `quant.Bar`

### 0.3 雙標的同構原則

`Step()` 不知道自己在跑 BTCUSDT 還是 ETHUSDT。標的差異透過：
- `params.SpawnPoint`（出生點，例如月度注資金額、最小訂單）
- `params.Chromosome`（染色體，由 GA 針對該標的的歷史數據獨立進化）

兩者完全傳達。內核程式碼**不**寫 `if symbol == "BTCUSDT"` 之類的分支。

## 1. 資產結構三態（Portfolio State）

### 1.1 三態定義

| 名稱 | Lot Type 標籤 | 語義 | 來源 |
|------|--------------|------|------|
| `DeadAsset` | `DEAD_STACK` | 宏觀長期底倉，原則只進不出 | 宏觀引擎吸入 |
| `FloatAsset` | `FLOATING` | 微觀浮動倉，可自由買賣 | 微觀引擎管理 |
| `ColdSealedAsset` | `COLD_SEALED` | 冷封存底倉，**永不釋放** | 用戶建立 Instance 時指定的封存比例 |

> 註：本文件用 `Asset` 抽象表示「標的資產」（BTC 或 ETH），具體欄位在 Go 結構中可叫 `DeadBTC` / `DeadETH` 或保持泛型 `DeadAsset`，但**內核計算只用泛型語義**。

### 1.2 通用會計公式

```
TotalAssetQty   = DeadAsset + FloatAsset + ColdSealedAsset
TotalEquity     = USDTBalance + TotalAssetQty × Price
ReserveFloor    = micro_reserve_pct × TotalEquity
SpendableUSDT   = max(0, USDTBalance - ReserveFloor)
CurrentMicroWeight = (FloatAsset × Price) / TotalEquity     // 注意：分子只算 FloatAsset，不含 Dead/ColdSealed
```

- `micro_reserve_pct`：微觀層保留資金比例（出生點參數，不進化），預設 `0.25`
- `ReserveFloor`：保留作為微觀引擎下次加倉的彈藥，宏觀引擎**不能**動用

### 1.3 標的對應關係

| 交易對 | 標的資產 | USDT 報價 |
|--------|---------|-----------|
| BTCUSDT | BTC | USDT |
| ETHUSDT | ETH | USDT |

每個 Instance 只持有一個標的 + USDT 兩種資產，不做跨標的切換。

## 2. 市場狀態感知層

### 2.1 四態分類

`MarketState` 結構體：

```go
type MarketState struct {
    State                  string  // "NORMAL_BULL" | "NORMAL_BEAR" | "QUIET" | "EXTREME"
    TimeDilationMultiplier float64 // 給宏觀引擎，1.0=正常，>1.0=擴展時間窗口加速定投
    BetaMultiplier         float64 // 給微觀 Sigmoid，1.0=正常，>1.0=加速調倉
    IsQuiet                bool    // true 時微觀粉塵訂單歸零
}
```

### 2.2 判斷規則

判斷依賴兩個維度：**趨勢** 與 **波動**。

**趨勢維度**：基於 EMA 排列
- `EMA50 > EMA200 × 1.005`（多 0.5% 緩衝避免黏連）→ `Bullish`
- `EMA50 < EMA200 × 0.995` → `Bearish`
- 否則 → `Sideways`

**波動維度**：基於最近 30 根 4h K 線的 σ（對數收益率標準差）相對於長期 365 天的分位數
- σ 占比 > 90% 分位 OR 24h（6 根 4h bar）絕對漲跌幅 > 8% → `HighVol`
- σ 占比 < 30% 分位 → `LowVol`
- 否則 → `MidVol`

**四態映射**：

| 趨勢 | 波動 | State | TimeDilation | BetaMul | IsQuiet |
|------|------|-------|--------------|---------|---------|
| Bullish 或 Sideways | LowVol | `QUIET` | 1.0 | 0.5 | **true** |
| Bullish | MidVol | `NORMAL_BULL` | 1.0 | 1.0 | false |
| Bearish | MidVol | `NORMAL_BEAR` | **1.5** | 1.0 | false |
| Sideways | MidVol | `NORMAL_BULL`（保守歸類） | 1.0 | 1.0 | false |
| 任意 | HighVol | `EXTREME` | 1.0 | **2.5** | false |

### 2.3 設計理由

- **熊市加速定投**（`TimeDilation=1.5`）：跌的時候撿便宜是 DCA 的精髓
- **極端時加速調倉**（`BetaMul=2.5`）：暴漲暴跌時 Sigmoid 響應加快，避免錯失關鍵點位
- **盤整時降頻**（`BetaMul=0.5` + `IsQuiet=true`）：減少手續費損耗
- **不上 HMM/馬可夫**：規則式四態算力低、可解釋、能跑通；機率模型留作 Phase 14+ 升級

### 2.4 邊界情況

- 數據不足（K 線少於 200 根 4h bar，約 33 天）→ 強制返回 `QUIET` 並印警告
- σ 計算結果為 0（極稀有，例如停盤）→ 視為 `QUIET`

## 3. 信號與目標函數框架

策略採用「**意圖層 + 過濾層**」二段結構：

```
意圖層：
  - Macro Engine  → MacroIntent  (BUY only, 進入 DeadStack)
  - Micro Engine  → MicroIntent  (BUY/SELL, 操作 FloatStack)
  - Release Logic → ReleaseIntent (DeadStack → FloatStack 帳本轉換)

過濾層（內建在各引擎內部）：
  - 楔形區過濾（防粉塵）
  - 最小訂單閾值（10.1 USDT）
  - SpendableUSDT clamp
  - 全局止損熔斷
```

## 4. 宏觀引擎（Macro Engine）

### 4.1 設計理念

宏觀引擎負責**長期累積底倉**，本質是「**動態加速版的月度 DCA**」：
- 每月固定預算
- 平日按日均勻分配
- 行情極端時加速消化預算
- 月底死線兜底（防資金閒置）
- **只買不賣**（賣出由微觀引擎或人工釋放規則處理）

### 4.2 月度預算機制

每個自然月的 1 號 0:00 UTC，宏觀引擎分配當月預算：

```
MonthlyBudget = MonthlyInjectUSDT  (出生點參數，不進化)
DailyBudget   = MonthlyBudget / DaysInMonth
```

**狀態追蹤**（持久化於 `RuntimeState`）：

```go
type MacroRuntimeState struct {
    CurrentMonthYearMonth string  // "2026-05"
    MonthlyBudget         float64
    SpentThisMonth        float64
    LastMacroBuyBarTime   int64
}
```

### 4.3 每 tick 決策邏輯

```
1. 跨月檢查：input.Now 落入新月 → 重置 MonthlyBudget / SpentThisMonth = 0
2. 計算當日剩餘額度：
     RemainingDays = DaysInMonth - (DayOfMonth - 1)
     RemainingBudget = MonthlyBudget - SpentThisMonth
     BaseDailyTarget = RemainingBudget / RemainingDays
3. 應用市場狀態加速：
     AcceleratedTarget = BaseDailyTarget × MarketState.TimeDilationMultiplier × MacroAccelerator(若 EXTREME)
4. 死線兜底：
     若 DayOfMonth >= MacroDeadlineDays（預設 28）且 RemainingBudget > 0：
         OrderUSD = RemainingBudget   // 全部花掉
     否則：
         OrderUSD = min(AcceleratedTarget, RemainingBudget, SpendableUSDT)
5. 過濾：
     若 OrderUSD < 10.1 → OrderUSD = 0（不下單）
6. 同 4h bar 不重複：
     若 LastMacroBuyBarTime == input.LatestBarTime → OrderUSD = 0
7. 產出 MacroIntent { Action: BUY, Engine: MACRO, LotType: DEAD_STACK, AmountUSDT: OrderUSD }
```

### 4.4 鐵律

- **只產出 BUY 意圖**，絕不產出 SELL
- 訂單金額必與 `SpendableUSDT` 做 clamp（不能超過可用資金）
- 小於 10.1 USDT 的訂單不執行（粉塵拦截）
- 同一 4h bar 內最多下一次（避免重複）

### 4.5 複利如何發生

宏觀引擎用「絕對 USDT 額度」（`MonthlyInjectUSDT`），**不**做相對權益的滾動。但用戶可選擇將「外部新注資」設為 `MonthlyInjectUSDT × (1 + growthRate)`，由 SaaS 訂閱層處理（不在策略內部複利）。

策略內的複利完全由**微觀引擎**承擔：`TheoreticalUSD = DeltaWeight × TotalEquity`，TotalEquity 隨權益增長 → 訂單規模隨之放大 → 自然複利。

## 5. 微觀引擎（Sigmoid 動態天平）

### 5.1 核心公式

```
EffectiveBeta  = max(0.01, Beta × MarketState.BetaMultiplier)
InventoryBias  = clamp(CurrentMicroWeight, 0, 1) - 0.5
Exponent       = EffectiveBeta × Signal + Gamma × InventoryBias
TargetWeight   = 1 / (1 + exp(Exponent)),  clamp(0, 1)
DeltaWeight    = TargetWeight - CurrentMicroWeight
TheoreticalUSD = DeltaWeight × TotalEquity
```

`TheoreticalUSD > 0` 時為 BUY 訂單金額（USDT），`< 0` 時為 SELL（abs 值對應賣出資產的 USDT 等價）。

### 5.2 Signal 三因子合成

```
X1_MeanRev  = -(Price - EMA21) / max(σ21, SigmaFloor)         // 偏離均線（負值=偏低=看多）
X2_Momentum = log(Price / EMA21) × 5                          // 動量強度
X3_Breakout = (Price - max(Closes[-21:])) / max(σ21, SigmaFloor)  // 突破近 21 根高點

Signal = SignalW_MeanRev × X1_MeanRev
       + SignalW_Momentum × X2_Momentum
       + SignalW_Breakout × X3_Breakout
```

固定常量（不進化）：
- `MicroSignalEMABars = 21`
- `MicroSignalStdDevBars = 21`

### 5.3 楔形過濾（Wedge Filter）

```
VolatilityRatio = clip(MAVAbsChange(closes, MicroVolRatioShortBars=16) /
                       MAVAbsChange(closes, MicroVolRatioLongBars=112), 0.1, 3.0)
                  // 數據不足時回傳 1.0

過濾規則：
  if abs(TheoreticalUSD) >= 10.1:
      OrderUSD = TheoreticalUSD                 // 直接下單
  elif 0 < abs(TheoreticalUSD) < 10.1:
      if !MarketState.IsQuiet AND
         (abs(DeltaWeight) >= WedgeDeltaThr OR VolatilityRatio >= WedgeVolRatioThr):
          OrderUSD = sign(TheoreticalUSD) × 10.1   // 強制最小訂單
      else:
          OrderUSD = 0
  else:
      OrderUSD = 0
```

### 5.4 設計哲學（弹簧系統解讀）

```
Signal           = 外力（市場信號）
InventoryBias    = 弹簧恢復力（離 0.5 中性點越遠拉力越大）
Beta             = 弹簧剛度
Gamma            = 是否啟用弹簧（0=純信號驅動，>0=疊加均值回歸）
VolatilityRatio  = 楔形過濾，控制安靜期粉塵
```

### 5.5 微觀層硬釋放

當 Signal 強烈看空、`OrderUSD < 0` 但 `FloatAsset × Price < |OrderUSD|` 時：
- 從 `DeadAsset`（非 ColdSealed、不限老化時間）中**強制**轉換等量資產為 `FloatAsset`
- 補足後再執行賣出
- 此轉換寫 `AuditLog`，標記 `event_type=hard_release`

## 6. DeadAsset 釋放規則

### 6.1 軟釋放（Soft Release）

每次 `Step()` 都會檢查：

```
條件 1：DeadAsset lot 老化時間 >= DeadAgingMonths（染色體，預設 6 個月）
條件 2：當前 FloatAsset × Price / TotalEquity < CurrentMicroWeight 目標值的 80%
        （表示微觀層彈藥不足）

滿足兩條件時：
  ReleaseQty = min(
      DeadAsset_eligible × MaxReleasePct,        // 不超過合格 lot 的 MaxReleasePct
      MicroWeightGap × TotalEquity / Price       // 不超過微觀缺口
  )
  將 ReleaseQty 從 DEAD_STACK lot 轉為 FLOATING lot（保留原始成本）
  寫 AuditLog，event_type=soft_release
```

### 6.2 硬釋放（Hard Release）

見第 5.5 節。

### 6.3 鐵律

- `IsColdSealed=true` 的 lot **任何情況下不可被釋放**
- 釋放只更新 SaaS 帳本（lot type 標籤），**不**向 Agent 下發 TradeCommand
- 每次釋放必寫 `AuditLog`

## 7. 可進化參數契約（Chromosome）

### 7.1 染色體欄位（13 個，全部進化）

| 欄位 | 邊界 [min, max] | 預設值 | 步長 GeneStep | 語義 |
|------|----------------|--------|---------------|------|
| `Beta` | [0.1, 5.0] | 1.5 | 0.1 | Sigmoid 激進係數 |
| `Gamma` | [0.0, 2.0] | 0.5 | 0.05 | 倉位偏置（弹簧剛度） |
| `SigmaFloor` | [0.001, 0.05] | 0.005 | 0.001 | σ 下限，防止除零 |
| `SignalW_MeanRev` | [-2.0, 2.0] | 0.8 | 0.1 | 均值回歸因子權重 |
| `SignalW_Momentum` | [-2.0, 2.0] | 0.4 | 0.1 | 動量因子權重 |
| `SignalW_Breakout` | [-2.0, 2.0] | 0.3 | 0.1 | 突破因子權重 |
| `WedgeDeltaThr` | [0.01, 0.1] | 0.03 | 0.005 | 楔形權重變動閾值 |
| `WedgeVolRatioThr` | [1.2, 2.5] | 1.5 | 0.05 | 楔形波動率閾值 |
| `MacroAccelerator` | [1.0, 3.0] | 1.5 | 0.1 | EXTREME 行情下宏觀加速倍率 |
| `MacroDeadlineDays` | [25.0, 30.0] | 28.0 | 1.0 | 月底死線觸發日（整數，clamp 後 round） |
| `DeadAgingMonths` | [3.0, 24.0] | 6.0 | 1.0 | 底倉老化釋放門檻（整數） |
| `MaxReleasePct` | [0.05, 0.3] | 0.15 | 0.01 | 單次最大釋放比例 |
| `TargetMicroWeightFloor` | [0.05, 0.3] | 0.15 | 0.01 | 微觀層權重下限（保證帳戶留有彈藥） |

### 7.2 結構約束（Clamp 必修復）

1. **三個 SignalW 至少一個非零**：`abs(W_MeanRev) + abs(W_Momentum) + abs(W_Breakout) >= 0.1`，否則設 `W_MeanRev = 0.5`
2. **整數欄位 round**：`MacroDeadlineDays`、`DeadAgingMonths` clamp 後再 `round()`
3. **楔形閾值能觸發最小訂單**：`WedgeDeltaThr × min(用戶資金) >= 10.1`（軟提示，由 GA 自然淘汰違反者）
4. **TargetMicroWeightFloor < 0.5**：強制低於 Sigmoid 中性點，避免微觀層永遠想加倉

### 7.3 出生點 SpawnPoint（不進化、Epoch 級凍結）

```go
type SpawnPoint struct {
    Policy CapitalPolicy `json:"policy"`
    Risk   RiskBounds    `json:"risk"`
}

type CapitalPolicy struct {
    MonthlyInjectUSDT  float64  // 用戶設定，例如 100 USDT/月
    InitialCapitalUSDT float64  // 用戶設定，例如 1000 USDT
    ColdSealedPct      float64  // 用戶設定，例如 0.1 = 10% 永久封存
    MicroReservePct    float64  // 預設 0.25
}

type RiskBounds struct {
    GlobalStopLossPct float64  // 全局止損，例如 0.5 = 權益跌至 50% 強制停止
    FeeRate           float64  // Binance 現貨 0.001 (0.1%)
    MinOrderUSDT      float64  // 10.1（Binance BTCUSDT 最小訂單 10 USDT，留 0.1 安全餘量）
    LotStepSize       float64  // BTC: 0.00001, ETH: 0.0001
    LotMinQty         float64  // BTC: 0.00001, ETH: 0.0001
}
```

SpawnPoint 在 GA Epoch 啟動時凍結，全種群共享，**不**參與代內交叉變異，**不**進入基因組指紋。

### 7.4 預設冠軍（DefaultSeedChromosome）

當 DB 無精英基因時，GA 第一個個體使用上表「預設值」欄位的組合作為種子。此種子是「保守的中性配置」，不保證跑得贏 DCA，由 GA 進化找出更優解。

## 8. StrategyInput / StrategyOutput 契約

### 8.1 StrategyInput

```go
type StrategyInput struct {
    // 時間
    NowMs            int64    // 當前 tick 的時間戳（ms），由外圈傳入，禁止 time.Now()
    LatestBarTimeMs  int64    // 最新已完成 4h bar 的開盤時間戳

    // K 線（已 ACL 降級）
    Closes     []float64  // 收盤價序列，按時間升序，至少 200 根
    Timestamps []int64    // 對應的開盤時間戳序列

    // 帳戶快照
    Portfolio PortfolioSnapshot

    // 策略內部運行時狀態（由上次 Step 持久化）
    Runtime RuntimeState

    // 標的元資訊（用於下單轉換，內核不應做業務判斷）
    Symbol      string   // "BTCUSDT" / "ETHUSDT"
    LotStepSize float64  // 數量精度
    LotMinQty   float64  // 最小數量
    MinOrderUSD float64  // 最小訂單 USDT 金額（10.1）
}

type PortfolioSnapshot struct {
    USDTBalance     float64
    DeadAsset       float64  // 標的資產數量
    FloatAsset      float64
    ColdSealedAsset float64
    Price           float64  // 當前最新 tick 價格
}

type RuntimeState struct {
    Macro MacroRuntimeState  // 見 §4.2
    // 未來擴展：micro state, cooldown timers 等
}
```

### 8.2 StrategyOutput

```go
type StrategyOutput struct {
    Intents []TradeIntent  // 本 tick 產出的交易意圖（可空）
    Releases []ReleaseIntent  // 帳本轉換意圖（可空）
    NewRuntime RuntimeState  // 更新後的策略內部狀態，外圈負責持久化
    Diagnostics map[string]float64  // 調試用，例如 {"signal": 0.32, "target_weight": 0.45, ...}
}

type TradeIntent struct {
    Action     string   // "BUY" / "SELL"
    Engine     string   // "MACRO" / "MICRO"
    LotType    string   // "DEAD_STACK" / "FLOATING"
    AmountUSDT float64  // BUY 用此欄位
    QtyAsset   float64  // SELL 用此欄位
}

type ReleaseIntent struct {
    Kind       string   // "soft_release" / "hard_release"
    QtyAsset   float64  // 釋放數量（DEAD → FLOATING 的標的資產數量）
    SourceLotIDs []uint  // 來源 lot ID 列表（依老化排序）
}
```

### 8.3 Step() 主流程（按順序）

```
func Step(in StrategyInput, p Params) StrategyOutput {
    // 1. 數據窗口檢查
    if len(in.Closes) < 200 { return EmptyOutput(in.Runtime) }

    // 2. 帳戶會計
    totalEquity := in.Portfolio.USDTBalance + 
                   (in.Portfolio.DeadAsset + in.Portfolio.FloatAsset + in.Portfolio.ColdSealedAsset) * in.Portfolio.Price
    reserveFloor := p.SpawnPoint.Policy.MicroReservePct * totalEquity
    spendableUSDT := math.Max(0, in.Portfolio.USDTBalance - reserveFloor)
    currentMicroWeight := (in.Portfolio.FloatAsset * in.Portfolio.Price) / totalEquity

    // 3. 市場狀態
    marketState := quant.ComputeMarketState(in.Closes, in.NowMs)

    // 4. 宏觀引擎
    newMacroState, macroIntent := macro.Decide(
        in.Runtime.Macro, in.NowMs, spendableUSDT,
        marketState, p.Chromosome.MacroAccelerator, p.Chromosome.MacroDeadlineDays,
        p.SpawnPoint.Policy.MonthlyInjectUSDT, in.LatestBarTimeMs,
    )

    // 5. 微觀引擎
    microIntent, microDiag := micro.Decide(
        in.Closes, in.Portfolio.Price, currentMicroWeight, totalEquity,
        marketState, p.Chromosome,
    )

    // 6. 底倉釋放
    softRelease := release.MaybeSoftRelease(in.Portfolio, currentMicroWeight, p.Chromosome)
    hardRelease := release.MaybeHardRelease(microIntent, in.Portfolio)

    // 7. 全局止損熔斷
    if totalEquity <= p.SpawnPoint.Policy.InitialCapitalUSDT * (1 - p.SpawnPoint.Risk.GlobalStopLossPct) {
        return HaltOutput(in.Runtime)  // 清空意圖，不產出新訂單
    }

    // 8. 組裝輸出
    return StrategyOutput{
        Intents: collectIntents(macroIntent, microIntent),
        Releases: collectReleases(softRelease, hardRelease),
        NewRuntime: RuntimeState{ Macro: newMacroState },
        Diagnostics: mergeDiag(microDiag, marketStateDiag(marketState)),
    }
}
```
