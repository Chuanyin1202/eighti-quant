# 20 — 進化計算引擎（GA Engine）

**文件目標：** 定義 EightiQuant 的 GA 黑盒引擎規格。引擎**完全不知道任何具體策略**，只透過 `EvolvableStrategy` 8 動詞接口操作策略提供的基因。新增策略無需修改 `engine.go`。

---

## 0. 核心定位

引擎是**純計算執行緒**：接收策略提供的基因空間 + 適應度評估器，對種群執行多代進化，交付最優基因（Champion）。

**輸入**：策略 `EvolvableStrategy` 接口 + 歷史 `[]float64 closes` + 進化配置
**輸出**：challenger 基因包 JSON，寫入 DB，等待人工 Promote

**鐵律**：`internal/saas/ga/engine.go` 禁止 `import` `strategies/` 任何包。

---

## 1. 探索窗口定義

### 1.1 多時段坩堝

Epoch 啟動時引擎一次性從 DB 拉取本 Epoch 所需的全部 `closes` 序列（type `[]float64`，已 ACL 為 close-only）。在此基礎上建構四個滾動窗口：

| 窗口 | 評分區間 | 適應度權重 |
|------|---------|-----------|
| 10y（全量） | 最早至最新 bar | 0.40 |
| 5y | 1825 天 | 0.30 |
| 2y | 730 天 | 0.20 |
| 6m | 183 天 | 0.10 |

每個窗口在評分區間之前再預留最多 1200 天 warmup（不計入評分）。

**嚴禁未來資料洩露**：每個窗口的評估區間從 `EvalStartMs` 開始，warmup 在之前。

### 1.2 基因空間
策略透過 `Sample` / `Mutate` / `Crossover` 三個動詞描述基因空間。引擎不直接讀欄位名。

### 1.3 出生點凍結（Epoch 級）
`SpawnPoint`（資金政策 + 風險邊界）在 Epoch 啟動時固定，全種群共享，**不**參與代內變異，**不**進入指紋。

`POST /api/v1/evolution/tasks` 支援 `spawn_mode`：
- `inherit`：繼承當前 champion 的 SpawnPoint
- `random_once`：排隊時抽樣一次
- `manual`：請求體填寫

## 2. 進化生命週期

### 2.1 種群初始化
種群預設 `Population = 300`：
- 有 DB 精英時：10% 原樣 / 40% 強化變異（prob=0.15, scale=1.5）/ 50% 全隨機
- 無 DB 精英時：第一個體為 `DefaultParams()`，其餘全隨機

索引 0 始終為當前種子（reproducible）。

### 2.2 並發評估
`Workers = min(NumCPU, PopulationSize)`。每個 worker 獨佔 Adapter 實例，無共享可變狀態。

### 2.3 錦標賽選擇
`TournamentSize = 3`，隨機抽 3 取最優。

### 2.4 均勻交叉
每維度 50% 概率獨立從父代選取。子代交給策略 `Clamp` 修復結構約束（在策略 `Crossover` 動詞內處理）。

### 2.5 加性高斯變異
每維度獨立 Bernoulli 概率 `MutationProbability`（預設 0.15）；變異量 `NormFloat64() × GeneStep × MutationScale`（預設 Scale=1.0）。

### 2.6 精英保留
`Elitism = 8`，Top N 直接入下一代。

### 2.7 收斂檢測 + 變異斜坡
連續 `EarlyStopPatience = 5` 代無改善 → `mutProb *= 1.25`、`mutScale *= 1.25`。
上限 `MutationProbabilityMax = 0.55`、`MutationScaleMax = 3.0`。
觸頂仍無改善 → Early Stop。

### 2.8 指紋快取
策略 `Fingerprint` 對基因向量按精度 1e-6 哈希（FNV-1a-64）。引擎在 Epoch 內偵測重複，命中跳過評估。預期命中率 15-30%。

### 2.9 收斂交付
最優基因經 `EncodeResult` 寫入 DB 為 `challenger`。**不自動 Promote**，等人工。

## 3. 適應度黑盒

### 3.1 多窗口坩堝分數

```
Alpha       = ROI_strategy - ROI_GhostDCA
SliceScore  = Alpha - DDPenaltyCoef × max(0, MaxDD_strategy - MaxDD_GhostDCA)
              預設 DDPenaltyCoef = 1.5
```

**Window-Local Fatal + Recency-aware Penalty**：

| Window | FatalDDThreshold | SliceScore_fatal |
|--------|------------------|------------------|
| 6m | 0.50 | -200 |
| 2y | 0.75 | -100 |
| 5y | 0.88 | -10 |
| 10y | 0.95 | -10 |

**為何 recency-aware**：6m / 2y 內大跌 = 「最近還在賠錢」必須 block。5y / 10y 含完整熊市，閾值放寬。

`ScoreTotal = 0.40×Score_10y + 0.30×Score_5y + 0.20×Score_2y + 0.10×Score_6m`

無短路、無 sentinel。fatal 個體（≤ -19）與正常（>0）有壓倒性落差。

### 3.2 Ghost DCA 基準（per-tick + carry + MinOrder）

baseline 採用**與策略 Macro 引擎相同**的累積式 DCA 機制：

```
BarsPerDay = 24 / aggregation_hours
maintain pendingBudget (跨月 carry over)
maintain monthlyBudget = MonthlyInjectUSDT, spentThisMonth = 0

每根完整 bar:
  1. 跨月重置 monthlyBudget / spentThisMonth
  2. RemainingBars = (RemainingDays-1) × BarsPerDay + RemainingBarsToday
     PerTickBase = RemainingBudget / max(RemainingBars, 1)
     pendingBudget += PerTickBase
  3. CanFire = (pendingBudget >= MinOrderUSDT) OR IsDeadline
  4. CanFire 時：
     - IsDeadline → 盡量花光剩餘月度預算（min with SpendableUSDT）
                    未花掉部分 carry 到 pendingBudget
     - else → orderUSD = min(pendingBudget, monthlyBudget - spentThisMonth)
              if orderUSD < MinOrderUSDT: orderUSD = 0
              else: pendingBudget -= orderUSD
```

**為何 baseline 必須與策略對稱**：
- 共用 cadence、共用 MinOrder 約束、共用 carry 機制
- 策略唯一差異是 `TimeDilation` / `Accelerator` 加速
- alpha 純粹反映加速時點價值，不靠 baseline 結構性劣勢偽造

### 3.3 ROI 計算
Modified Dietz：剔除注資跳變對 NAV 的影響。

```
ROI = (期末權益 - 期初權益 - Σ(現金流_i)) /
      (期初權益 + Σ(現金流_i × 加權因子_i))
加權因子_i = (總天數 - 注資發生日_i) / 總天數
```

### 3.4 評估順序
4 個窗口全跑完，無短路。實作上仍按短到長（6m → 10y）順序方便監控。

## 5. 結果交付與基因角色

### 5.1 三態狀態機

| 角色 | 含義 |
|------|------|
| `challenger` | 進化產出，等待人工審批 |
| `champion` | 當前活躍冠軍，驅動實盤實例 |
| `retired` | 歷史冠軍，存檔 |

### 5.2 Promote 流程（防 split-brain）

#### 5.2.1 事務協議

```sql
BEGIN; -- REPEATABLE READ

-- 1. advisory lock 序列化（即使無 champion 也能鎖）
SELECT pg_advisory_xact_lock(
    hashtextextended('promote:' || ? || ':' || ?, 0)
);

-- 2. 退役當前 champion（無 row 也 OK）
UPDATE gene_records
  SET role = 'retired', retired_at = NOW()
  WHERE strategy_id = ? AND symbol = ? AND role = 'champion';

-- 3. 晉升 challenger（必須驗證仍是 challenger）
UPDATE gene_records
  SET role = 'champion', activated_at = NOW()
  WHERE id = ? AND strategy_id = ? AND symbol = ? AND role = 'challenger';
-- 影響 0 行 → ROLLBACK + 回 409 Conflict

-- 4. audit log
INSERT INTO audit_logs (event_type, payload) VALUES ('promote', ?);

COMMIT;

-- 5. commit 成功後才 DEL Redis cache
DEL champion:{strategy_id}:{symbol}

-- 6. wake up BLOCKED instances
UPDATE strategy_instances
  SET state = 'RUNNING'
  WHERE strategy_id = ? AND symbol = ? AND state = 'BLOCKED';
```

#### 5.2.2 Partial Unique Index（DB 兜底）

```sql
CREATE UNIQUE INDEX IF NOT EXISTS uniq_active_champion
ON gene_records (strategy_id, symbol)
WHERE role = 'champion';
```

寫入 `internal/saas/store/indexes.sql`，啟動時 db.go 在 AutoMigrate 後 Exec。

#### 5.2.3 Preflight（檢測 duplicate）

啟動順序：AutoMigrate → preflight → indexes.sql

```go
func championIndexPreflight(db *gorm.DB) error {
    var dupes []struct {
        StrategyID string
        Symbol     string
        Count      int
    }
    db.Raw(`
        SELECT strategy_id, symbol, COUNT(*) as count
        FROM gene_records WHERE role='champion'
        GROUP BY strategy_id, symbol HAVING COUNT(*) > 1
    `).Scan(&dupes)

    if len(dupes) > 0 {
        return fmt.Errorf("duplicate champions detected: %+v (manual cleanup required)", dupes)
    }
    return nil
}
```

啟動 fail → 進程退出 + 告警，不容忍跳過。

#### 5.2.4 Manual Cleanup
若 preflight fail：
1. SELECT 所有 duplicate champion 列出
2. 人工選正確 champion（通常最新 activated_at）
3. UPDATE 其他改 retired
4. 寫 audit log `manual_dedup`
5. 重啟 SaaS

#### 5.2.5 Known Limitation: Rolling Deploy Race
當前 preflight 流程**假設單一 SaaS process**（Phase 0-13 主線符合）。
Phase 14+ 上 cluster 時要重新設計（leader election / blue-green / CONCURRENTLY）。

### 5.3 Cron Tick Champion 載入（version-aware）

```go
var ErrNoChampion = errors.New("no champion available")

func (m *InstanceManager) loadChampion(strategyID, symbol string) (*Champion, error) {
    key := fmt.Sprintf("champion:%s:%s", strategyID, symbol)

    // 1. cache 嘗試
    var cachedC *Champion
    if cached, gerr := m.redis.Get(key); gerr == nil {
        cachedC = decodeChampion(cached)
    }

    // 2. 原子 DB 讀（單次查詢，role='champion' 強條件，避免 promote race）
    var rec GeneRecord
    err := m.db.
        Where("strategy_id = ? AND symbol = ? AND role = 'champion'", strategyID, symbol).
        First(&rec).Error
    if errors.Is(err, gorm.ErrRecordNotFound) {
        return nil, ErrNoChampion
    }
    if err != nil { return nil, err }

    // 3. 版本驗證
    if cachedC != nil && cachedC.ID == rec.ID && cachedC.ActivatedAt == rec.ActivatedAt {
        return cachedC, nil
    }

    // 4. DB → cache 寫回
    c := buildChampion(&rec)
    m.redis.SetEx(key, encodeChampion(c), 24*time.Hour)  // best-effort
    return c, nil
}
```

### 5.4 BLOCKED 自動恢復

兩條路徑並存：
1. **被動**：cron 也掃 BLOCKED 實例做輕量 `loadChampion` 探測（最壞 < 1 min）
2. **主動**：promote 事務 commit 後 `UPDATE strategy_instances SET state='RUNNING' WHERE state='BLOCKED'`（最壞 < 1s）

SaaS 重啟必須 load `RUNNING` + `BLOCKED`（`STOPPED` / `ERROR` 不載入）。

## 7. EvolvableStrategy 接口（重述）

見 `10-策略框架接口.md` §3。引擎透過 8 動詞操作策略提供的 `Gene any`：

| 動詞 | 職責 |
|------|------|
| `StrategyID` | 唯一標識 |
| `Sample(rng)` | 隨機採樣 |
| `Mutate(g, prob, scale, rng)` | 加性高斯變異 |
| `Crossover(p1, p2, rng)` | 均勻交叉 + 結構修復 |
| `Fingerprint(g)` | FNV-1a-64 雜湊（精度 1e-6） |
| `Evaluate(ctx, g, plan)` | 多窗口坩堝評估 |
| `DecodeElite(json)` | 從 ParamPack JSON 解碼 |
| `EncodeResult(g, spawn)` | 序列化為 ParamPack JSON |
| `Verify(ctx, g, spawn, bars, lotStep, lotMin)` | 全量驗證回測 |

### 7.1 EvaluablePlan（只讀上下文）

```
EvaluablePlan
├── Pair, StrategyID
├── Spawn *SpawnPoint
├── LotStep, LotMin
├── Windows []CrucibleWindow  // 4 個窗口含 closes 切片與權重
├── DCABaselines []DCABaseline // 與 Windows 一一對應，預計算
└── AggregateCache             // 預聚合指標（可選）
```

DCA 基線在 Epoch 啟動時一次性計算。

### 7.2 包位置約束

`<Strategy>Evolvable` 實作放在 `internal/saas/ga/<strategy>_evolvable.go`，**不**放策略包內，避免 `策略包 → ga → 策略包` 雙重循環依賴。

### 7.3 多策略並行
不同 (strategy_id, symbol) 可並行 GA。同 (strategy_id, symbol) 禁止並行（`EpochService.currentTaskByKey` 互斥）。
